# 科普工作台系统前后端对接文档

文档信息

| 项    | 内容                                     |
| ---- | -------------------------------------- |
| 系统名称 | 科普工作台（CloudRise Science-Pop Workbench） |
| 调用方  | 前端 SPA（浏览器端）                           |
| 提供方  | 后端服务 / 各能力网关（AI、知识库、短信、企微、对象存储）        |

## 1. 功能需求概述（我方想要实现的功能）

| 编号     | 功能      | 前端现状              | 后端需提供                           | 优先级 |
| ------ | ------- | ----------------- | ------------------------------- | --- |

| B2     | AI 内容生成 | `USE_MOCK_AI` 模拟  | 真实大模型生成接口（活动方案/推文/文案）           | P0  |
| B3     | 登录与权限   | 本地验证码模拟           | 注册/登录/JWT/RBAC（管理员·运营·志愿者·家长）   | P0  |
| B4     | 服务端分页   | 前端内存分页            | 报名/数据列表服务端分页（>500 条不卡）          | P1  |
| B5     | 文件对象存储  | IndexedDB 本地存图    | 照片/海报上传 COS/OSS 返回 URL          | P1  |
| B6     | 真实数据分析  | 随机 mock 图         | 聚合统计接口（报名/签到/满意度趋势）             | P2  |
| B7     | 主题工作流视频 | 仅脚本/分镜            | 视频流水线 7 接口 + SSE 进度             | P2  |
| KB     | 知识库语义检索 | `USE_MOCK_KB` 演示库 | 健康探测/集合列表/语义检索接口                | P0  |
| SMS    | 短信提醒    | 前端方案+本地日志         | 短信网关发送接口                        | P0  |
| WECHAT | 企微机器人回复 | 关键词本地回复           | 智能回复代理（转发企微 webhook）            | P1  |
| GEO    | 地理围栏校验  | 固定坐标判定            | 服务端半径/坐标校验接口                    | P1  |

## 2. 前后端职责边界

| 职责    | 前端（调用方）                        | 后端（提供方）                   |
| ----- | ------------------------------ | ------------------------- |
| 界面与交互 | 负责全部 UI、表单校验、加载态、错误提示          | 不介入                       |
| 参数组装  | 按契约组装请求体、设置鉴权头                 | 校验参数合法性并返回结构化错误           |
| 网络请求  | `fetch` 调用、超时（8s/10s）、失败重试 1 次 | 保证接口幂等、返回规范 envelope      |
| 业务计算  | 轻量前端计算（标签/状态）                  | 重计算、聚合、AI 推理、检索排序         |
| 数据存储  | 仅缓存/演示（localStorage/IndexedDB） | 唯一数据源：持久化、备份、权限隔离         |
| 安全    | 透传 Token、不硬编码密钥                | 密钥管理、JWT 签发、RBAC、审计日志、限流  |
| 文件    | 选择/预览，上传后展示 URL                | 接收二进制、落 COS/OSS、返回可访问 URL |

## 3. 接口对接方式（通用规范）

### 3.1 基础地址

- 生产：`https://{生产域名}/api`
- 测试：`https://test-{测试域名}/api`
- 知识库为独立服务时，地址可在前端「设置 → 知识库服务地址」单独配置（默认回退 `/api/kb/search`）。

### 3.2 通用约定

- 请求/响应均为 `application/json; charset=utf-8`。
- 时间统一 ISO 8601（`2026-08-30T15:30:00+08:00`）。
- 成功响应统一信封：`{ "code": 0, "message": "ok", "data": { ... } }`。
- 失败：HTTP 状态码表达传输层错误；业务错误在 body 内用 `code>0` 表达（见 3.4）。
- 跨域：浏览器直连需后端开启 CORS（`Access-Control-Allow-Origin` 白名单 + `Allow-Credentials`）；建议生产走同域网关反向代理，避免暴露密钥。

### 3.3 鉴权方式

- **API Key（Bearer Token）**：用于 AI、知识库等服务间调用。前端在「设置」配置 `aiApiKey` / `kbApiKey`，请求头 `Authorization: Bearer <key>`。
- **用户 JWT**：用于账号类接口。登录后前端在后续请求携带 `Authorization: Bearer <jwt>`；后端校验并解析 `orgId` 做数据隔离。

### 3.4 错误码约定

| HTTP         | 含义                       | 前端处理                   |
| ------------ | ------------------------ | ---------------------- |
| 200          | 成功（或 body.code=0）        | 正常渲染                   |
| 400          | 参数错误                     | 提示字段级红字                |
| 401          | 鉴权失败（Token 缺失/过期/Key 错误） | 提示「请检查 API Key / 重新登录」 |
| 403          | 无权限（RBAC 拒绝）             | 提示无权限                  |
| 404          | 接口/资源不存在                 | 提示「接口地址配置错误」           |
| 408/前端 abort | 超时（8s/10s）               | 提示超时并自动重试 1 次          |
| 422          | 业务校验不通过（如手机号已存在）         | 提示具体原因                 |
| 429          | 限流                       | 提示稍后重试                 |
| 500/503      | 服务异常/不可用                 | 降级到演示数据（KB）或提示         |

## 4. 接口明细

### 4.1 AI 内容生成

- **地址**：`POST /api/ai/generate`
- **鉴权**：Bearer（aiApiKey）
- **超时**：10s，失败重试 1 次
- **请求参数**

| 字段     | 类型     | 必填 | 说明                         |
| ------ | ------ | -- | -------------------------- |
| prompt | string | 是  | 完整提示词（前端已按场景拼装：活动方案/推文/文案） |

- **响应结构**

```json
{ "code": 0, "message": "ok", "data": { "content": "推文正文……", "strategy": "已应用策略：温情亲子向 + 故事化叙事" } }
```

- **前端调用点**：`App.fetchAIContent(prompt)` → `App.ai.genTweet / mock`

### 4.2 知识库 — 健康探测

- **地址**：`GET /api/kb/health`
- **鉴权**：Bearer（kbApiKey）
- **超时**：8s
- **响应**：HTTP 2xx 即视为可达且鉴权有效；401 视为 Key 错误。
- **前端调用点**：`App.kb.connectTest()`（「设置 → 连接测试」与知识库页自动探测）

### 4.3 知识库 — 集合/索引列表

- **地址**：`GET /api/kb/collections`
- **鉴权**：Bearer（kbApiKey）
- **响应结构**

```json
{ "code": 0, "message": "ok", "data": { "collections": [ { "id": "science", "name": "科学启蒙", "desc": "0-12岁认知" } ] } }
```

- 前端兼容 `collections` / `items` / 裸数组三种形态。
- **前端调用点**：`App.kb.listCollections()`（知识库页筛选器）

### 4.4 知识库 — 语义检索

- **地址**：`POST /api/kb/search`
- **鉴权**：Bearer（kbApiKey）
- **超时**：10s，失败重试 1 次
- **请求参数**

| 字段         | 类型     | 必填 | 说明                          |
| ---------- | ------ | -- | --------------------------- |
| query      | string | 是  | 检索文本                        |
| collection | string | 否  | 集合 id；`all` 或不传表示全部         |
| top_k      | int    | 否  | 返回条数，默认 5                   |
| filters    | object | 否  | 附加过滤，如 `{ "tags": ["安全"] }` |

- **响应结构（后端返回以下任一字段均可，前端 `_normalize` 自动归一化）**

```json
{
  "code": 0, "message": "ok",
  "data": { "results": [
    { "id": "d2", "title": "户外活动安全须知", "content": "……", "snippet": "……",
      "source": "社区活动安全管理规范", "url": "", "score": 0.92, "tags": ["安全","亲子"], "collection": "safety" }
  ] }
}
```

- **归一化后前端统一结构**：`{ id, title, content, snippet, source, url, score, tags, collection }`
- **前端调用点**：`App.kb.query(text, opts)`（知识库页搜索）

### 4.5 账号 — 发送验证码

- **地址**：`POST /api/account/send-code`
- **鉴权**：无（防刷由后端限流 + 图形码）
- **请求参数**：`{ "phone": "138xxxx", "scene": "login|bind" }`
- **响应**：`{ "code": 0, "message": "ok", "data": { "sent": true } }`（真实环境由短信网关下发，前端不接触明文码）

### 4.6 账号 — 登录 / 换绑手机号

- **登录**：`POST /api/account/login` → `{ "phone", "code" }` 返回 `{ "data": { "token": "<jwt>", "phone": "138xxxx" } }`
- **换绑**：`POST /api/account/bind-phone`
  - 请求：`{ "oldPhone", "oldCode", "newPhone", "newCode" }`
  - 校验：原号验证码、新号验证码均服务端校验；新号不能等于原号且格式合法（前端已做基础校验，后端为权威）。
  - 响应：`{ "code": 0, "message": "ok", "data": { "phone": "139xxxx" } }`
- **前端调用点**：`App.account.login / changePhone`（账号中心弹窗）

### 4.7 短信提醒发送

- **地址**：`POST /api/sms/send`
- **鉴权**：Bearer / JWT
- **请求参数**

| 字段       | 类型       | 必填 | 说明                                      |
| -------- | -------- | -- | --------------------------------------- |
| phones   | string[] | 是  | 接收手机号列表                                 |
| template | string   | 是  | 模板标识，如 `activity_remind`                |
| params   | object   | 否  | 模板变量，如 `{ "活动名":"", "时间":"", "地点":"" }` |

- **响应**：`{ "code": 0, "message": "ok", "data": { "taskId": "SMS-xxx", "count": 12 } }`
- **前端调用点**：`App.ui.renderSms()` 发送按钮（短信提醒页，含模板变量预览）

### 4.8 企微机器人回复

- **地址**：`POST /api/wechat/bot`
- **鉴权**：Bearer / JWT
- **请求参数**：`{ "question": "如何申请科普补贴？" }`
- **响应**：`{ "code": 0, "message": "ok", "data": { "reply": "……", "docs": [ <知识库条目> ] } }`
- 后端可转发至企微 webhook 或结合知识库检索生成答案。
- **前端调用点**：`getBotReply(t)`（社群助手气泡）

### 4.9 地理围栏校验

- **地址**：`POST /api/geo/check`
- **请求参数**：`{ "lat": 30.66, "lng": 104.10, "center": {"lat":30.6598,"lng":104.1043}, "radius": 100 }`
- **响应**：`{ "code": 0, "message": "ok", "data": { "inside": true, "distance": 35 } }`
- **前端调用点**：现场签到坐标校验

### 4.10 业务数据同步（B1，约定式）

以活动与报名为例（其余资源同构）：

- `GET /api/activities` → 列表；`POST /api/activities` → 新建
- `GET /api/activities/:id/registrations?page=1&size=20` → 分页报名
- `POST /api/registrations` → 报名写入（返回带 `id` 与服务端时间戳）
- 统一 envelope + JWT 鉴权 + `orgId` 数据隔离。

### 4.11 文件上传（B5）

- **地址**：`POST /api/upload`
- **请求**：`multipart/form-data`（字段 `file`）
- **响应**：`{ "code": 0, "message": "ok", "data": { "url": "https://cdn.xxx/act/xxx.jpg" } }`
- 前端上传后仅存储返回的 URL。

## 5. 数据交互流程

### 5.1 知识库检索（典型）

```
前端输入关键词
  → App.kb.query(text, opts)
  → POST /api/kb/search（Bearer + 10s 超时）
  → 后端检索排序返回 results[]
  → _normalize 归一化
  → App.ui 渲染卡片（标题/摘要/来源/标签/分数）
失败：401→提示检查 Key；超时→重试1次；仍失败→提示错误（不降级，保证数据真实）
```

> 注：演示态（`USE_MOCK_KB=true`）下列表/检索失败会降级到内置演示库；真实态不做降级。

### 5.2 登录与换绑手机号

```
登录：输入手机号 → 发送验证码(后端短信网关) → 填码 → POST /api/account/login → 存 JWT
换绑：校验原号验证码 → 输入新号 → 发新号验证码 → POST /api/account/bind-phone → 更新本地账号
```

### 5.3 短信提醒

```
选择活动/报名人 → 预览模板变量 → 点发送
  → POST /api/sms/send（phones/template/params）
  → 后端调短信网关 → 返回 taskId
  → 前端写本地发送日志（仅记录，不下发）
```

### 5.4 业务数据同步（切换 localStorage）

```
启动加载 → GET /api/activities 等拉取
操作（报名/签到）→ POST/PUT 写回 → 200 确认
离线：本地缓存读写，恢复网络后增量同步（后端定版）
```

## 7. 联调步骤与注意事项

### 7.1 联调步骤

1. **后端**提供测试环境地址与 API Key，按第 4 节实现各接口并满足统一信封。
2. **前端**在「设置」填入 KB 地址/Key，或将 `USE_MOCK_*` 置 `false` + 改 `App.config` 地址。
3. **冒烟**：
   - 知识库：连接测试返回可达 → 搜「儿童安全」有结果且按 score 排序。
   - 账号：注册/登录拿 JWT；换绑新旧号均通过。
   - 短信：发送返回 taskId（测试环境走沙箱号，不发真实短信）。
   - AI：活动方案/推文返回真实 content。
   - 数据：报名写入后刷新不丢。

### 7.2 注意事项

- **密钥安全**：AI/KB 的 Key 仅用于服务间调用；用户类接口用 JWT，Key 勿下发到浏览器明文长期存储。
- **超时与重试**：前端已设 8s/10s 超时 + 重试 1 次，后端请勿在超时内做超长阻塞，必要时用异步任务 + 轮询/SSE。
- **返回兼容**：知识库接口返回字段名可能不同，前端 `_normalize` 已兼容 `results/data/items`、以及 `title/name`、`content/text/snippet/answer` 等别名；后端尽量贴近 4.4 结构以减少前端映射。
- **不降级原则**：真实态下接口失败应明确报错，不静默回退演示数据。
- **分页与容量**：报名超过 500 条必须由后端分页（B4），前端不再全量内存渲染。
- **数据隔离**：多组织/多社区场景按 `orgId` 隔离，后端在查询层强制注入。
- **验收反推**：建议后端先按本文「响应结构/示例」给出 Mock 返回，前端即可联调，再补真实实现。

### 7.3 验收标准（前端侧）

- [ ] 知识库连接测试 2xx；检索返回≥1 条且按相关度排序。
- [ ] 登录/换绑全流程通过，JWT 生效。
- [ ] 短信发送返回 taskId（测试环境不真实外发）。
- [ ] AI 生成返回非空 content。
- [ ] 报名/活动数据清缓存后仍在（后端为源）。
- [ ] 错误码 401/404/429/500 前端均有对应提示且不白屏。
